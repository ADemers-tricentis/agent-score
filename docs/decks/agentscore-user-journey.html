1
Fleet
Outcome
You spot the agent that's quietly failing before it turns into a shipped incident.
Every agent, one status board.
•A–F grade + 0–100 composite, recalculated after every scoring run
•Verdict (Ship/Hold/Reject) plus a reliability read across sessions (pass^k)
•Sorted by what needs attention first, not alphabetically
2
Setup
Outcome
You find out whether your agent is any good without asking engineering to touch a line of its code.
Copy-paste, not a build.
•One tenant API key covers every agent you connect — not one key per agent
•OTLP endpoint + auth header shown inline, ready to paste into your exporter
•Or hand the same instructions to your coding agent to wire it for you
3
Waiting for traces
Outcome
You see everything actually running in your fleet — including agents nobody remembered to log.
Nobody names it yet.
•Received → parked → recognized from behavior → ready, shown live
•Known agents match an existing profile automatically, no manual linking
•Brand-new agents get created on the spot from what their traces reveal
4
Name your agent
Outcome
The agent gets scored against the right criteria from minute one, not a generic default.
Confirm, don't invent.
•Name & type pre-filled from detected behavior, not left for you to guess
•One field to confirm or edit, not a form to build from scratch
5
Launch
Outcome
Monitoring starts the moment production traffic does — nothing sits unscored while you finish setup.
One click, five steps behind it.
•Registers the agent, connects OTel, and provisions a scoring profile at once
•Opens Run #1 immediately — it's already collecting, no second click needed

6
Project overview
Outcome
You can't ship a verdict that's actually built on three sessions.
Nothing scored on thin data.
•Run #1 sits open and visibly in progress, not silently pending
•Scoring stays locked until there's enough trace volume for a score to mean something
•"Simulate traces" is a demo helper only — real runs wait on real traffic
7
Scoring tab
Outcome
You set the standard once, in your own words — it keeps re-checking it.
Configure the bar, in plain language.
•Describe the agent via Guided fields (a form) or an Expert spec (you write it)
•Compare runs side-by-side the moment a second run exists
•Auto-scores daily at 02:00 UTC, so the bar stays current with no manual trigger
8
Score now
Outcome
You get a score you can defend, not a number nobody can explain.
On demand, or on schedule — not either/or.
•Disabled until there's enough trace volume — no button to click too early
•Parallel LLM judges score every session against the configured evals at once
•A real scoring pass with visible token cost and latency, not a placeholder
9
Run view
Outcome
You can answer "better or worse" with one session, not a vibe.
The audit trail.
•Every session in the run, its composite score, listed and sortable
•Export any session as a calibration case to tune future scoring
•Compared directly against the prior run — up, down, or flat
10
Session view
Outcome
You leave with a decision to act on, and a paper trail for why.
The why, not just the what.
•3–6 dimension bars, scaled to what actually matters for that agent type
•Attribution: root cause, supporting evidence, and a confidence score
•Ship / Hold / Reject, exportable as Markdown or JSON for what's next
the decision this feeds
