2. Security findings and gates
   - The recommendation from users: if a security dimension fails, the agent is marked "do not ship" regardless of other dimensions.
   - Concern: a weighted score can hide a security failure. A high overall score can mask a PII or prompt-injection problem.
   - SPEAKER_00 argues against threshold-based or weight-based logic and against changing the score, because users could game it by editing their profile.
   - Direction: use a separate gate layer. A gate is a rule that must pass before an agent ships. Gates can cover security, PII, compliance, or domain-specific rules.
   - Terminology: "gate" is preferred over "guardrail." Customers use "guardrail" for runtime blocking of tool calls or prompt injection.
   - Proposed model: flag individual traces, then let a gate look at the last N traces. Example: if any of the last 10 traces has a security flag, the gate stops the ship.
   - Severity levels were proposed. A leaked SSN would rank higher than an exposed dev API key.
   - Versioning: a new version should start clean until it is tested. Flags are tied to versions.
   - Tim noted that gates make stimulation testing (synthetic inputs that probe for failures) necessary. If gates only fire on real user traffic, they miss attacks that never happen in production.
   - Open risk: users may bypass or disable gates. Need a way to notify, and a way to reset a flag with a reason (for example, "this is dev").

3. Ad hoc task scoring (non-trace input)
   - Current model: async, trace-based scoring.
   - Proposed: a sync path that scores an arbitrary input (transcript, file, or output) against a profile. This is a "task" path, separate from the "agent" path.
   - Use case: CI or build pipelines. A build runs test cases, gets a score, and fails if the score is bad.
   - Likely delivery: a CLI, with uploads to S3 or similar handled behind the scenes. Non-technical users should not need to upload to S3 directly.
   - Benefit: may remove the need for a tracing integration for these cases.
   - Tim researched AWS AgentCore Evaluations and Strands Evals. AgentCore requires users to write Python for stimulation. Strands is easier.

## Decisions Made
- Security findings will not be handled by weighting. The direction is a separate gate layer on top of per-trace flags.
- Use the term "gate" instead of "guardrail" in product language.
- A new agent version starts clean and is evaluated independently.
- Ad hoc task scoring (non-trace input, CI-friendly) is worth exploring. It is not yet committed.
