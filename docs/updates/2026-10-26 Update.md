## Summary
Andrew checked status on trace unredaction and whether trace-tenant work can start before that finishes. The call then covered how a coding agent creates evals (match an existing profile first), what a user should see right after connecting MCP, and a decision to ship the current build now and land MCP when it is ready. Separately, Gainsight is blocked until GA, PMs want an internal eval now that EvalClaw is shut down, and Andrew wants the next customer conversations timed to the new MCP setup.

## Key Discussion Points
1. **Trace unredaction, then the trace tenant**
   - Andrew asked whether unredaction is the last step. He treated the answer as yes.
   - He asked whether anything can be done for the trace tenant before unredaction. He accepted that this waits.

2. **Lior's update**
   - Andrew's reaction was that the update was exciting. The content of that update is not in the transcript.

3. **User-created evals and dynamic scoring**
   - Andrew confirmed that "the user creating the evals" includes dynamic scoring.
   - The user's coding agent comes up with the dimensions, the profile, and the evals.
   - Flow Andrew restated: try to match an existing profile, and if nothing matches, continue from there. He was satisfied with that.

4. **MCP docs and the cold start**
   - Andrew asked for documentation of MCP capabilities to hand a user at connect time. What he found is back-office dev docs, not customer docs. Logging into the back office took the usual multi-password path.
   - He does not want every tool call documented. The agent already knows the tools.
   - The gap is the cold start: the user is connected, has an agent, and does not know the next move.
   - Preferred shape: a short "now that you're connected, here's what you can do" (start a scoring run, and the other jobs already described in the docs), written as how you do it through MCP. He wants to avoid writing the same docs twice.
   - Fallback he also liked: the MCP connection itself ends by telling the user the next step, for example to ask it to start a scoring run.
   - Andrew will connect MCP himself and walk the flow.

5. **Login, Tosca Cloud tenant, and other products**
   - Open question Andrew raised: what happens when a user logs in now, and do we know which tenant they are in when they use Tosca Cloud?
   - His read of the answer: we should know, and we do not.
   - Direction he stated: do not integrate with the other products yet. Anything integrated now would have to be taken back out later.

6. **Connecting to whatever the customer already uses**
   - A common request is "I build agents in X, can Agent Score connect to it?" Names he listed: Datadog, Azure Foundry, Palantir Foundry, and Google in the same breath as Palantir Foundry (the Google line is muddy in the audio).
   - He wants a working session on how that connection would actually work.
   - His default: push from their side, because they keep finer control.

7. **A team that closed the ticket**
   - Someone told that team to use Agent Score. They did not know what the product does, and they closed the Jira ticket.
   - What Andrew told them: their agent should score the requirements and the test cases. Agent Score scores that agent and says whether it is doing the right thing. The contact then said he might be right. Andrew assumes that is why the ticket was closed.
   - He expects more feedback from them. He wants to start those conversations once MCP and the new setup are in, so the sessions are live tests of that setup.

8. **AI safety and governance**
   - Early requests to use Agent Score for AI safety and AI governance. Andrew's view is the product is already most of the way there, and the open work is choosing the path. He is still working that through.

9. **Redaction and privacy**
   - Andrew agreed with a point (the other side of it is missing) that a discussed approach removes the redaction and privacy problem, because that data is not available to the user.

10. **Gainsight**
    - Seats are full. They will not give one up for a beta product that is not GA.
    - If Agent Score goes GA, they said they will buy a seat. Andrew relayed that the seats are expensive. Gainsight is not available to this team until then.

11. **Self-improvement loop, then ship**
    - Andrew liked using the current setup as a self-improvement loop before MCP is further along. He called out signal-to-noise as the hard part: the loop starts manufacturing its own noise.
    - He asked to be told when it is pushed, and he will start using it.
    - Decision on the call: push what is ready now. Andrew plays with that. MCP goes out when it is ready.

12. **Feature flags**
    - A fragment about security ("you don't get any more security") is not clear enough to record as a decision.
    - Andrew's rule for a flag: it exists to answer a question (try it on a small group, or you are not sure you will keep the feature). Once the question is answered, delete the flag.
    - In beta he would rather ship and roll back than wait. He is fine with flags or with a process.
    - One enforcement idea he floated, not decided: a linter or a pre-merge hook that rejects a PR once the flag count crosses a limit. He also said Claude could enforce the same check.

13. **Internal dogfood now that EvalClaw is gone**
    - Getting this into Agent Score matters for internal adoption. PMs want to know how their agents are doing. EvalClaw is no longer running (audio sounded like "eval clause").
    - What Andrew was told, and he flagged it as secondhand: it cost about $20k a month, so they shut it down. He does not know whether the API keys were actually turned off. Zimmerman mentioned it in passing. Do not treat the dollar figure as confirmed.
    - Andrew looked at the repo. ATA had something like 15 to 20 evals, which is not a huge suite. His guess is they ran every eval on every trace, possibly every trace that landed in Better Stack. He does not know the setup well enough to say that is what happened.
    - He asked Tim to push this, or to poke Henry, so it gets into Agent Score.

## Decisions Made
- Trace-tenant work waits until unredaction is done.
- Ship the current build now. Andrew starts using it. MCP ships when it is ready.
- MCP help for users explains what they can do after connect (start a scoring run, and the rest). It does not document each tool call. A closing instruction from the MCP itself is an acceptable version of the same thing.
- Do not integrate with other Tricentis products yet.
- External platform connections should default to push on the customer's side.
- A feature flag answers a question and then gets removed. No decision yet on a mechanical cap.
- Gainsight waits until GA.
