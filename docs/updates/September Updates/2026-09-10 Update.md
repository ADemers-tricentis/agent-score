## Summary
The team reviewed progress on standing up the AgentScore AWS environment and the main thing still blocking real customer feedback: authentication/SSO. Plan is two fully separated environments (US and EU, different accounts/infrastructure) so EU customer data stays in-region, mirroring how the TAIS cluster is already set up by tenant key. The current hard blocker is Entra ID SSO provisioning (an IT ticket to configure the app URL/ID) plus a compliance stance from Matt against any broad/customer data in the environment. Infrastructure (RDS, S3, Helm charts) is largely provisioned and moving toward black-box validation. Andrew flagged that 6-7 interested companies keep hitting the same "can't do anything yet" wall and committed to finding a way to unblock.

## Key Discussion Points
1. **Two-environment architecture (US + EU)**
   - Fully separated: different accounts, infrastructure, everything.
   - Enables streaming customer data while keeping EU data in the EU region.
   - Same tenant-key-based model the TAIS cluster already uses; the change needed is in the EC2/TAIS setup, which is reportedly already handled.
2. **Compliance blocker on customer data**
   - Matt's latest position: no customer/broad data whatsoever in the environment.
   - Andrew is looking for a way around this so real feedback isn't indefinitely delayed.
3. **SSO / authentication provisioning**
   - App uses Entra ID (the Tricentis corporate login), not a Tosca login.
   - Blocked on an IT ticket: someone must configure a few entries (app URL, ID). Once configured, Lior takes that data, sets the variables, and deploys — then it works end to end.
   - Lior asked Stefan about reusing the existing Tosca/Okta identity in the AWS account to move faster; Stefan said it's impossible. Lior will push further with Anastasia and is open to bringing alternative solutions, but someone needs to own the decision.
   - Broader frustration: no one is willing to take on risks that Lior considers non-risks; new initiatives should be able to operate like isolated startups ("innovation at speed"), not "innovation in turtles."
4. **Chat feature in AgentScore**
   - Andrew asked whether the chat is a custom build or the shared AI chat repo.
   - It's Lior's own implementation — protected/secured, scoped to the specific points needed. Andrew to try it and give feedback before extending.
5. **Infrastructure / deployment status (Sohil)**
   - RDS and S3 are provisioned.
   - Late change to the RDS instance type ("medium") came in before SRE deployment; Matt approved doing it directly via Terraform. Not blocking the black-box validation test.
   - Helm charts done for all services (3 core / 5 services); plan is step-by-step deploy + test, then Terraform, running two tracks in parallel, deployed "same to same" as EC2/TAIS.

## Decisions Made
- Proceed with two fully separated US and EU environments, EU data staying in-region.
- RDS instance-type change ("medium") to be applied directly via Terraform (Matt approved).
- Keep Lior's custom chat implementation for now; Andrew to trial it before deciding on additions.
