3. Ingest authentication / API-key security problem
   - Backend requests are normally authenticated via token at the API gateway. Ingest is different: clients send traces using a generated URL + API key, which is not auto-revoked/rotated like a token.
   - Risk: a stolen API key could be used to flood the service with malicious, excessive, or oversized spans; no automatic verification/revocation exists today.
   - Proposed solution: middleware inside the API gateway (similar to a "web/worker" pattern Lior built previously) that passes requests to a checker before reaching the worker, protecting the system.
   - Stefan has approved the approach; Lior will loop in Omer so the team isn't surprised by the out-of-the-box solution.
