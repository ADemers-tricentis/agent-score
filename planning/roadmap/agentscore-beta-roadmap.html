AgentScore Roadmap

Beta onboarding and self-improvement

Last updated 10-22-2026 · Horizons: Now / Next / Later

Target persona

A semi-technical user who can create agents but does not know how to configure traces, instrumentation, or agent updates. They create or evaluate agents and make the final call before an agent ships to production.

North star

Get as many users, including internal users, as possible using AgentScore regularly. The product must prove its value: users must actually use it and benefit from it. Users should be able to onboard, score, and improve their agents as simply and quickly as possible.

Target user flow

From sign-up to measurable improvement. Step numbers match the feature cards below. Step 7 is the Now part of dynamic scoring. The scorecard and session grouping stay Next and are not numbered steps.

Simplify onboarding

The path from signing up to a best-fit profile and eval set, with no manual instrumentation, trace configuration, or agent changes. Steps 1 to 7. Step 7 is the Now part of dynamic scoring.

Why it matters

The persona can create agents but cannot configure traces. Every step of friction between sign-up and first score loses a beta user. Self-service onboarding is a High recurring ask from Wolters Kluwer and L'Oreal. This is the direct path to the north star.

Goal: a user signs up, connects an agent, and gets the best-fit profile and evals automatically. If none fit, AgentScore creates them and explains why. Backoffice admins are out of the loop for tenant creation.

Stimulation testing

AgentScore profiles an agent, runs targeted tests, and scores the results, so users can test without waiting for organic traces. Steps 8 to 11, after the profile and evals are set.

Why it matters

Scenario bank and simulation testing is the top High ask across Meta (x2), L'Oreal, Tritusa, Eaton, and PG&E, and the pivotal gap for the Meta POC. It makes AgentScore an end-to-end testing solution across the ADLC.

Goal: an agent is profiled, given the test categories that fit it, tested automatically, and scored, with improvements generated from the results. No more waiting on organic traces for scoring.

Self-improvement loop

AgentScore feeds improvements back to the user's agent, re-scores the new version, and repeats. Steps 12 and 13. Showing gains and reporting (steps 14 and 15) are Later.

Why it matters

Fast loops where an agent is evaluated, improved, and retested are how AgentScore wins. Nailing this loop is the single biggest source of value for users, and it turns a one-time test into repeat use.

Goal: an agent improves across versions as improvements are fed back and the new version is re-scored.

Dynamic scoring

The rest of dynamic scoring, after step 7. A scorecard written for each agent, plus session grouping so a score covers a whole task or conversation. Fixed profiles stay available during beta. Not a numbered step in the flow.

Why it matters

A fixed profile catalog force-fits agents that do not match it, and a score on one trace misses a multi-step task. Eaton reacted to editable success criteria, profiles, and weighted dimensions. New Vision accepted editable success criteria and custom dimensions. Automatic best-fit selection is already Now, in step 7. This card stays Next so stimulation testing is not blocked on the fuller model.

Goal: a user can score an agent on a richer scorecard across a whole session, without giving up the fixed profiles already in the product.
  • Per-agent scorecard
    Written for one agent, from a conversation with the owner, from the agent's traces and behavior, or from dimensions and weights the user sets. Runs beside the fixed profile catalog during beta.
    AI-15831In Progress. Custom checks and profiles are underway.
  • Session grouping
    Related traces are grouped into a task or conversation, and the score covers that whole session.

Trace data protection

Keeping sensitive information out of stored traces.

Why it matters

Tritusa raised compliance and PII flagging as a High blocker for regulated (bank and pharma) clients. Wolters Kluwer and Eaton raised data handling concerns. None blocked the first beta cohort.

Goal: regulated users can send traces without exposing PII or other sensitive data.

Quantitative cost function

Measurable improvements by category, each with a cost impact, backed by a quantitative model that puts a dollar or risk value on each. Step 14.

Why it matters

Showing impact such as "saves $X in token spend" proves the value of each improvement. A quantitative model makes those numbers defensible for the person who makes the final ship call.

Goal: every improvement carries a calculated cost or risk value the user can trust and compare.
